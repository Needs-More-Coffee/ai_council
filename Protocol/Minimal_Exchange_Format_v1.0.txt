MINIMAL EXCHANGE FORMAT v1.0
Governance Layer: Infrastructure (Subordinate to Kernel)

Purpose
The Minimal Exchange Format defines a structured, explicit, and transport-agnostic method for transferring information between personalities, governance voices, sessions, and instances.
It eliminates reliance on conversational history and implicit memory.

Design Principles
- Explicit over implicit
- Portable over conversational
- Attributable over blended
- Partial but declared over complete but inferred

Exchange Packet Structure
An exchange packet consists of five ordered blocks.
No block may be omitted without explicit declaration.

1. Context Block
Defines what problem space is being addressed.
Must include:
- Problem statement
- Scope boundaries
- Known constraints
- Known unknowns
No assumptions may appear here.

2. State Block
Defines what is currently treated as true.
Must include:
- Declared assumptions
- Fixed decisions (if any)
- Immutable constraints
All assumptions must be labeled as confirmed or provisional.

3. Personality Output Block
Exactly one personality may contribute to a single block.
The block must be labeled with:
- Personality name
- Personality version

Permitted contents vary by personality:
Designer:
- Candidate designs
- Candidate actions
- Design space boundaries

Analyst:
- Reasoning chains
- Assumptions and dependencies
- Limitations

Consultant:
- Options
- Tradeoffs
- Risks

Operations:
- Preconditions
- Steps
- Checks
- Failure conditions

4. Governance Voice Block (Optional)
If a governance voice is active, it may add:
- Prioritized constraints
- Protected values
- Unacceptable failure modes
No decisions may be made here.

5. Open Items Block
Must include:
- Unresolved decisions
- Blocking questions
- Required arbitration
If empty, must state: "No open items."

Exchange Rules
- No block may rely on unstated context
- No personality may contribute to multiple blocks
- No block may imply decisions not explicitly stated
- Packets may be partial but must declare limits

Invalid Exchange Conditions
An exchange packet is invalid if:
- Assumptions are implicit
- Outputs are unlabeled
- Multiple personalities contribute to one block
- Decisions are inferred rather than stated

Invalid packets must be rejected or halted.

End of Minimal Exchange Format v1.0
